reserved-word (error): Names that are reserved words on some engines

A column called rank, key or user works on SQLite and fails on MySQL, MariaDB
or PostgreSQL, because each engine reserves different words.

Every engine keeps a list of words that can't be names without quotes, and the
lists differ. PostgreSQL reserves user, only and array; MySQL and MariaDB
reserve key, index, range, rows and many more, and MySQL 8 added the names of
window functions such as rank, groups and row. SQLite reserves the fewest. The
table lists words people often give to tables and columns, each tried as a
column name on all four engines.

Example:
    CREATE TABLE t (id INTEGER, rank INTEGER)

    SQLite 3.45.1        no rows
    PostgreSQL 16.15     no rows
    MySQL 8.0.46         error: You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the r...
    MariaDB 10.11.14     no rows

The same on every engine:
    CREATE TABLE t (id INTEGER, rank_no INTEGER)

    SQLite 3.45.1        no rows
    PostgreSQL 16.15     no rows
    MySQL 8.0.46         no rows
    MariaDB 10.11.14     no rows

Pick another name, such as user_name, rank_no or sort_key. Quoting the name is
no portable way out: double quotes name a column on SQLite and PostgreSQL and
make a string on MySQL and MariaDB (see double-quotes), and backticks work on
SQLite, MySQL and MariaDB only (see backticks).
